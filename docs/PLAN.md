# Attract — 프로젝트 기획서

> 게임을 위한, 게임만을 위한 베어메탈 OS

- **작성일**: 2026-08-11
- **상태**: M3 완료, M4 진행 예정
- **성격**: 개인 학습 프로젝트 / 취미

---

## 1. 한 줄 정의

x86_64 베어메탈 위에서, **프레임 데드라인을 지키는 것을 최우선으로 설계된** 단일 목적 커널.
게임 콘솔의 펌웨어에 가깝고, 범용 OS가 아니다.

## 2. 왜 만드는가

- 새로운 것을 배우고 싶다는 욕구가 출발점. 결과물의 유용성은 목표가 아니다.
- 게임 개발자로서 매일 마주치는 문제(프레임 히칭, 입력 지연, 메모리 스파이크)를 **반대편에서** 이해하고 싶다.
- Zig라는 언어를 실전 규모로 익힌다.
- 저수준 감각(캐시, 할당 전략, 스케줄링)은 본업에도 그대로 돌아온다.

## 3. 무엇이 아닌가 (Non-goals)

이 항목이 이 문서에서 가장 중요하다. 유혹이 올 때마다 여기로 돌아온다.

| 안 하는 것 | 이유 |
|---|---|
| 리눅스 배포판 만들기 | SteamOS식 통합 작업은 배우는 게 "설정 방법"뿐 |
| 실기 배포 / 사용자 확보 | 취미. 남이 쓸 필요 없음 |
| GPU 드라이버 | 최신 GPU 문서가 비공개. 현실적으로 불가능 |
| 네트워크 스택 | 게임 OS 정체성과 무관하고 범위만 폭발 |
| POSIX 호환 / 이식성 | 단일 목적 OS. 호환성은 설계 자유를 뺏는다 |
| 멀티유저, 권한 분리, 보안 | 게임기에 로그인은 필요 없다 |
| 32비트, BIOS 부팅 | UEFI + x86_64만. 역사적 부채를 안 짊어진다 |

## 4. 설계 원칙

일반 OS와 **의도적으로 반대로 가는** 결정들. 이게 이 프로젝트의 정체성이다.

1. **처리량보다 레이턴시.** 스케줄러는 공정성이 아니라 프레임 데드라인을 지키기 위해 존재한다.
2. **예측 가능성 > 평균 성능.** 평균 1ms에 가끔 20ms 튀는 것보다, 항상 3ms가 낫다.
3. **런타임에 놀라지 않는다.** 메모리는 미리 폴트시키고, 할당은 가능한 한 부팅 시점에 끝낸다.
4. **측정할 수 없으면 개선할 수 없다.** 입력→화면 지연 측정을 커널에 내장한다.
5. **단순함이 기능보다 우선.** 범용성을 포기해서 얻는 단순함이 이 프로젝트의 이점이다.

## 5. 기술 스택

| 항목 | 선택 | 비고 |
|---|---|---|
| 언어 | Zig 0.16.0 (고정) | 크로스컴파일 내장, freestanding 1급 지원, comptime |
| 아키텍처 | x86_64 | |
| 펌웨어 | UEFI | 레거시 BIOS 미지원 |
| 테스트 | QEMU + OVMF | `zig build run` 한 방에 실행 |
| 초기 그래픽 | UEFI GOP 프레임버퍼 | 소프트웨어 렌더링 |
| 형상관리 | Git + 태그 | 마일스톤마다 태그 |

**버전 고정 정책**: `build.zig.zon`에 `minimum_zig_version = "0.16.0"`. Zig는 릴리스마다 API가 깨지므로, 마일스톤 사이에 버전을 올리지 않는다. 올릴 때는 별도 브랜치에서 몰아서.

## 6. 마일스톤

각 마일스톤은 **눈에 보이는 결과**로 끝난다. 중간에 멈춰도 손해가 아니도록 설계.

### M0 — 부트스트랩 (목표: 주말 1회)
- [ ] 저장소 생성, `build.zig` UEFI 타겟 설정
- [ ] QEMU + OVMF 실행 파이프라인 (`zig build run`)
- [ ] **시리얼(COM1, 0x3F8) 출력** ← 최우선. 이후 모든 디버깅의 통로
- [ ] UEFI SimpleTextOutput으로 화면에 글자
- [ ] 워치독 타이머 해제 (`setWatchdogTimer(0,0,0,null)`)

> **완료 조건**: `zig build run` 시 터미널에 `Attract v0.1 booting...` 출력

### M1 — 화면 (목표: 주말 1회)
- [ ] GOP 프로토콜 획득, 모드 정보를 시리얼로 덤프 (해상도 / 픽셀 포맷 / stride)
- [ ] 프레임버퍼에 그라디언트 그리기
- [ ] 비트맵 폰트로 화면에 텍스트 출력
- [ ] 더블 버퍼링

> **완료 조건**: 화면에 그라디언트 + 프로젝트 로고

### M2 — 게임 루프의 토대
- [ ] `exitBootServices()` — 펌웨어에서 완전히 독립
- [ ] GDT, IDT, 인터럽트 핸들러
- [ ] 고정밀 타이머 (TSC 또는 HPET)
- [ ] 프레임 페이싱 (60Hz 고정)
- [ ] 키보드 입력 (PS/2부터)

> **완료 조건**: 커널에 내장된 퐁 또는 스네이크가 60fps로 동작

### M3 — 메모리
- [ ] UEFI 메모리 맵 파싱, 물리 프레임 할당자
- [ ] 페이징 (가상 주소 공간 구성)
- [ ] 힙 할당자 — **프리폴트 / 고정 할당 전략** 적용
- [ ] 할당 통계 및 시리얼 리포트

> **완료 조건**: 동적 할당을 쓰는 데모가 프레임 드롭 없이 동작

### M4 — 스케줄링 (프로젝트의 핵심)
- [ ] 컨텍스트 스위칭, 커널 스레드
- [ ] **데드라인 기반 스케줄러** — 프레임 예산 개념 도입
- [ ] 지연 측정 계측 (입력 이벤트 → 화면 출력까지의 시간)
- [ ] 측정 결과를 화면에 오버레이

> **완료 조건**: 부하를 걸어도 프레임 데드라인 준수율이 수치로 확인됨

### M5 — 유저 모드 (최종 목표)
- [ ] 링 3 전환, 시스템 콜 인터페이스
- [ ] ELF 로더
- [ ] 최소 게임 API (프레임버퍼 접근, 입력, 타이머)
- [ ] 별도 빌드한 게임 바이너리 실행

> **완료 조건**: 커널 밖에서 빌드한 게임이 Attract 위에서 실행됨

### 보너스 (해도 되고 안 해도 되는 것)
- 오디오 (Intel HDA)
- USB 게임패드 (XHCI — 난이도 급상승)
- 어트랙트 모드: 입력이 없으면 데모 재생 (컨셉 완결용)
- 멀티코어 (SMP)

## 7. 프로젝트 완료 정의

**M5 도달 시 이 프로젝트는 성공으로 간주하고 종료한다.**

그 이후는 전부 보너스이며, 하고 싶으면 하고 아니면 안 한다.
"OS는 끝이 없다"는 특성 때문에 종료 지점을 미리 못 박아 둔다.

M2까지만 가도 배운 것이 남으므로 실패가 아니다.

## 8. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 초기 세팅에서 좌절 | 시리얼 출력을 최우선 목표로. 디버깅 수단부터 확보 |
| Zig 버전 업으로 코드 붕괴 | 버전 고정. 인터넷 예제는 버전 확인 후 참고 |
| std.os.uefi API 문서 부족 | `lib/std/os/uefi/` 소스를 직접 읽는다 |
| 범위 확산 (기능 추가 욕구) | 3장 Non-goals로 돌아온다 |
| 본업(게임 개발) 침식 | 주말 프로젝트로 한정. 평일 야근 금지 |
| 동기 소실 | 마일스톤마다 태그 + 스크린샷 + 일지. 진척이 보이게 |

## 9. 기록 규칙

- **개발 일지를 1일차부터 쓴다.** "3주 전에 이 값을 왜 이렇게 넣었지"는 반드시 발생한다.
- 형식: `docs/journal/YYYY-MM-DD.md` — 한 일, 막힌 것, 알게 된 것
- 마일스톤 완료 시 Git 태그 + 스크린샷 + README 갱신
- 하드웨어 매직 넘버에는 반드시 출처 주석 (스펙 문서 섹션 번호)

## 10. 참고 자료

- **sfiedler/zig_os** (codeberg) — Zig 부트로더+커널 입문 예제. Zig 버전별 태그 제공
- **Writing a Hypervisor in Zig** (hv.smallkirby.com) — 앞부분의 UEFI 부트로더 파트가 훌륭
- **nrdmn/uefi-examples** (github) — UEFI 프로토콜별 최소 예제
- **OSDev Wiki** — 막힐 때의 사전
- **UEFI Specification** — 원전. 의외로 잘 쓰여 있음
- **Serenity OS** — 취미 OS의 구조 참고 (그래픽/오디오까지 구현되어 있음)
- **xv6 / MIT 6.S081** — OS 전체 그림 잡기용 (C지만 짧고 완결적)
